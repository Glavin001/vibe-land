# vibe-land in Unreal Engine

`VibeCity` is a native Unreal Engine 5.8 client for the `/city` match. It connects to the same Rust
server as the browser, over WebTransport. Unreal only renders: decoding, the wire 4 city stream,
clock sync and interpolation live in vibe-land's shared Rust client core, which the web client is
moving onto too.

```
server ──WebTransport──▶ client-transport-wt ──bytes──▶ client-core ──frame──▶ client-core-ffi ──C ABI──▶ VibeLand plugin
         (Rust, ring TLS)    (session, manifest, QUIC)    (sans-IO, shared)     (static library)             (Unreal renders)
```

| Path | What |
|---|---|
| `client-core/` | Sans-IO core: decoders (`shared/src/net_client.rs`), the wire 4 stream (`perplayer`), players, coordinates, the frame |
| `client-transport-wt/` | Native WebTransport adapter (`wtransport`), the same stack as the server |
| `client-core-ffi/` | C ABI, static library; header generated by cbindgen and checked by a test |
| `unreal/VibeCity/` | The Unreal project; `Plugins/VibeLand` holds the client modules |
| `scripts/unreal/` | `build-core.sh`, `c-smoke.sh`, `build-editor.sh`, `demo.sh` |

## Run it

```bash
scripts/unreal/demo.sh
```

This starts the PhysX play server and the web client if they aren't running, then prints the
browser URL (`http://localhost:3003/city?match=citypp-demo`) and opens the Unreal client on the same
match. Add `--synthetic` for the physics-free test city (no GPU, but shots do nothing there).

The Unreal client only joins `citypp*` matches (city wire 4). On its own:

```bash
scripts/unreal/build-editor.sh
"/Users/Shared/Epic Games/UE_5.8/Engine/Binaries/Mac/UnrealEditor.app/Contents/MacOS/UnrealEditor" \
  unreal/VibeCity/VibeCity.uproject -game -windowed -VibeApi=http://127.0.0.1:4001 -VibeMatch=citypp-demo
```

The defaults live in `Config/DefaultGame.ini` (`[/Script/VibeLandNet.VibeNetSettings]`).

Console commands:
- `vibe.connect [api] [match]`
- `vibe.disconnect`
- `vibe.status`

The game log is `~/Library/Logs/VibeCity/VibeCity.log`. For scripted checks,
`-VibeShotDir=<dir> -VibeShotEvery=<s>` saves numbered screenshots; add `-RenderOffscreen` so
nothing needs to be on screen. `-VibeSpectate` flies a spectator over the city instead of playing.

## Playing

You play the web's `/city` in first person, with its controls (`client/src/input/bindings.ts`):

| Key | On foot | In a car |
|---|---|---|
| W A S D | move | throttle, brake, steer |
| Mouse | look | orbit the chase camera |
| Space | jump | handbrake |
| Left Shift | sprint | |
| C | crouch | |
| Left mouse | fire (held: at the server's rate) | |
| Right mouse | aim (45° view) | |
| 1 / 2 / 3, wheel | rifle, cannon, meteor strike | |
| V | melee | |
| E | enter the car within 4 m | leave the car |
| R | reset the city | reset the car |
| N | aerial camera; again to drop there | |
| Esc | free the mouse; click to take it back | |

The server simulates everything (a PhysX character controller for you, the city, the cars); the
client sends input and draws what the server streams, with a small bounded lead on your own
movement, as the web does on `/city`. Other players, cars (built from the parts the server
simulates), cannonballs, meteors, fractures and tracers come from the same stream the browser
reads, so a browser and an Unreal client on one match see and shoot each other. A dropped session
is rejoined on its own.

The web's character models and sounds are drawn from `/Game/VibeCity/Characters/` and
`/Game/VibeCity/Audio/` once imported; until then players are tinted stand-in figures and the game
is silent.

## Tests

```bash
cargo test -p vibe-client-core -p vibe-client-core-ffi   # the shared core, in-process against the match loop
cargo test -p web-fps-server --lib client_codec_roundtrip # every client packet against the server's codecs
scripts/unreal/play-tests.sh                              # the game, against a live PhysX server
```

`play-tests.sh` runs each Unreal test in its own game process on a fresh match: Esc and focus
(`VibeCity.Cursor`), walking at the server's speed and a shot's verdict (`WalkAndShoot`), aim and
city reset (`AimAndReset`), the cannon and a meteor that breaks the city (`CannonAndMeteor`),
melee and the aerial camera (`AerialAndMelee`), entering and driving a car (`Drive`). With a
browser on the same match, `VibeCity.Play.ShootRemote` hits the browser's player and
`VibeCity.Play.LookAtRemote` screenshots it.

## Building on macOS Sonoma 14.4 with Xcode 15.4

UE 5.8 expects the macOS 15 SDK. Xcode 15.4 has the 14.5 SDK, and it is the newest Xcode that runs
on 14.4. Four settings make the build work, with no engine changes:

1. **`Build/Mac/MacSDK14Compat.h`**, force-included from both `Source/*.Target.cs`
   (`bOverrideBuildEnvironment`). It supplies two declarations the engine headers take from the
   macOS 15 SDK. At runtime on macOS 14 the engine falls back to a plain lock and ignores the flag.
2. **No precompiled headers** (`bUseSharedPCHs = false`, `bUsePCHFiles = false`, and
   `PCHUsage = NoPCHs` per module). Apple clang 15 rejects a constrained `TOptional` destructor that
   the engine's shared PCH reaches. Every file therefore includes what it uses.
3. **UBA off.** `Saved/UnrealBuildTool/BuildConfiguration.xml` is committed on purpose; the rest of
   `Saved/` is ignored. The scripts also pass `-NoUBA`. UBA mangles the `-rpath @executable_path/…`
   link arguments.
4. **`-NoHotReload`** in `build-editor.sh`. Other editors running from the same engine make UBT use
   hot-reload names, which breaks linking between new modules.

The Rust library is built by `VibeClientCore.Build.cs`, which runs `scripts/unreal/build-core.sh`
during every Unreal build. That script:
- builds `-p vibe-client-core-ffi` only, for aarch64 with `MACOSX_DEPLOYMENT_TARGET=14.0`;
- fails if `aws-lc` is in the tree, since the client uses `ring`;
- records the system libraries the static library needs;
- stamps the header hash. The plugin refuses to build against a library made from a different
  header, and refuses to run on an ABI version mismatch.

Windows and Linux slot into the same `lib/<Platform>/<arch>/` layout later.
