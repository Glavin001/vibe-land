# Fast garage heightfield quality baseline — 2026-09-26

This measures the shipping driver predictor and spectator interpolator against the
previously captured native Vehicle2 garage trace. The serialized heightfield and
static props are loaded into the existing CPU/WASM query world. No new GPU
simulation, server or browser was started, and no predictor optimization was made.

The source demonstrably contains fast uneven-terrain driving:

- Peak horizontal speed: **80.4 km/h** (22.34 m/s).
- **4.68 seconds continuously above 54 km/h**, including 1.38 seconds above 72 km/h.
- 119 fast ticks (1.98 seconds) inside the washboard suspension lane.
- 3.63 m of terrain elevation change along the fast path.
- High-speed hill crest at source tick 498, followed by a full two-second measurement window.

Ten receive schedules × three seeds × driver/observer = **60 verdicts: 15 pass,
45 fail**. Every complete replay (poses, corrections and packet decisions) was run
twice and matched byte-for-byte on this runtime. All 30 driver cases fail at least
one target; 15 of the 30 observer cases pass. These are scenario/role verdicts, not
a count of failed unit tests.

The two new adversarial schedules add a 300 ms arrival blackout to mobile-like
receive delay/jitter/loss: washboard ticks [357,375), crest ticks [492,510).
The original eight receive schedules remain included. These are receive-channel
experiments on fixed server behavior, not an RTT or closed-loop uplink simulation.

Representative driver witnesses, seed 42:

Recovery begins only when the candidate stays within 15 cm of reference position,
10 cm vertically and 10 degrees of body tilt for 30 consecutive ticks, with fresh
accepted authority and no prediction freeze. The measured 56-tick delay precedes
that hold interval. Correcting one frame is insufficient. Correction magnitude
and final presented error are measured separately: a large internal correction
can occur even if visual smoothing keeps presented error small.

Terrain-only metrics prevent the initial idle period or easy straight driving
from diluting a bad crest/descent. Heightfield samples select the course; they
**do not establish signed collider clearance, wheel contact, takeoff or landing**.
Those native evidence channels remain missing. This tape is short and uses one
stock vehicle; it does not establish maximum-speed/custom-build coverage.

## Reproduce

From `client/`:

```sh
npm run netlab:vehicle:heightfield -- --out /tmp/vehicle-heightfield --check-measured
npm run netlab:vehicle:score -- /tmp/vehicle-heightfield/fast-crest-burst-42.json --check
npm run netlab:vehicle:compare -- ../docs/reports/vehicle-heightfield-v1/quality.json /tmp/vehicle-heightfield/quality.json --check
```

The first two commands intentionally return exit code 1 for this failing baseline.
`quality.json` contains terrain coverage/hash, pinned limits, reference
and WASM hashes, per-case scores and evidence hashes. `provenance.json` records the
candidate. Raw per-tick evidence is regenerated by the command; this run's copies
are at `/tmp/vehicle-heightfield-final/`.

Validation: **146 tests passed** across eight focused suites; client and toolkit
TypeScript checks passed. Analytic fault tests detect hidden vertical drift,
incorrect pitch, slow/flat/missing courses, truncated recovery, and a momentary
correction falsely presented as sustained convergence. Those tests verify the
measurement logic; the native replay above measures the shipping candidate.

and limitations.
