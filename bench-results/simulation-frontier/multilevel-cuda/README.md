# CUDA multilevel proof

Read [the result and integration report](../../../docs/multilevel-cuda-proof-2026-09-05.md).
This campaign is **not eligible for deployment**: the solver remains a standalone
harness with offline hierarchy construction.

- `source-v3.json` identifies final source, compiler generation, GPU and binary.
  `summary.json` uses only the final `*-v3.log` captures.
- `source-v0.*` retains float-storage/double-arithmetic history. `source-v1.*`
  retains the first true mixed-precision implementation. Intermediate v2 phase
  logs are historical; no final claim depends on an unretained v2 binary.
- `fixtures.json` lists the five binary fixture sizes, hashes and export flags.
  All were regenerated byte-for-byte from the final exporter. The shared graph
  is in `../contact-wrench/conditioning/single-building.json.gz`.
- `reproduce-fixtures.py` records the CPU-only reproduction commands and checks
  hashes. It assumes this machine's repository layout and writes under `/tmp`.
- `run-final.py` records CUDA commands, expected exit codes and output filenames.
  It does not acquire exclusive GPU access or stop the city by itself. Run it
  only inside the deployment's ownership-aware, zero-player wrapper, and use
  fresh output paths for later candidates.
- `summarize.py` validates and summarizes retained logs without GPU access.
- `logs/` keeps successful runs, unsuccessful approaches, the initial large-load
  assertion failure, CUDA memory checks and the denied Nsight-counter capture.
  Instrumented timings are excluded from the performance summary.
- `live-preserved.json` identifies the unchanged live server after the campaign.

No raw binary fixtures are duplicated in Git: each expands to roughly 70 MiB
from the committed graph and reference code. Original fixtures remain in `/tmp`
on this machine. The final exporter accepts gzipped graph input; set
`OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1` when reproducing it.
